### §3.10-4 的关键设计点

**不能把 selector 塞进 modelKey。** 两个是不同命名空间:Cascade 走真 modelKey +
selector=null,connect 走 modelKey=null + 真 selector,合并会撞进同槽。所以 bindingKey 是
三维 `caller\0(modelKey||*)\0(selector||*)`。

getApiKey 一直就收着 connectSelector,只是绑定键忽略了它 —— 两侧现在一致,没有新增参数
传递链。

**新引入的 API 陷阱(已用测试钉住)**:2 参数查询 `getStickyBinding(caller, null)` 读的是
`caller\0*\0*`,与 connect 写入的槽不同。生产能解析是因为 getApiKey 传了 selector;直接
调用者必须自己传。connect-sticky-e2e 有三处 2 参数查询因此要改。

**模块加载陷阱**:sticky-session.js 把 `STICKY_SESSION_ENABLED` 读进模块加载期的 `const`,
env 必须在 import 之前设好。我第一版测试用静态 import + beforeEach 设 env,7 条全失败且
失败原因与断言要测的东西毫无关系。用既有的 `loadFresh` 每测新导入模式。

## 4. 本会话新增的方法论(已写进 AUDIT-LEDGER 第三轮)

### 4.1 突变验证成为默认手段,而且它查的东西和对抗复核不重叠

对抗复核查"我的修复有没有引入新缺陷";突变验证查"我的测试有没有在测东西"。
本轮靠它查出**我自己写的 4 条测试是空转的**:

1. "两个行产出器都过滤" —— live 目录在新进程里是空的,producer 2 压根不产行
2. "空响应不缩小并集" —— 带空贡献者的并集算术上本来就不变,**断言错了后果**
3. `sawTable ? free : null` 的区分没有任何断言钉住(谓词对 null 与空集合回答相同)
4. 一条恒真断言 `assert.ok(x.length >= 0)`

**新判别标准(比旧的更早生效)**:问"这条断言在什么输入下会失败?"答不出具体输入,
它就没在测东西。旧标准"功能坏掉这条断言会失败吗"需要先想象一个缺陷,新的只需要
看断言本身。

### 4.2 突变验证前必须先证明 baseline 非零 —— 本轮连拿 4 次假 SURVIVED

全部是 harness 一个测试都没跑。本机 shell 是 **zsh**:

```
node --test $TESTS        # 不做词分裂,两个路径当一个参数 → Could not find 'a.js b.js'
read A B < <(cmd)         # 进程替换配 read 读不到值
grep --include=*.js       # 未加引号被当 glob 吃掉
```

`pass=0 fail=0` **不是**"守卫没抓到",是"没测量"。用 `${=VAR}` 或数组。

### 4.3 去掉一个 latch 不够,外面可能还有一层同类门禁

`trySyncConnectCatalog` 只能从 `fetchAndMergeModelCatalog` 里被调到,而那个函数被
**Cascade** 的 per-key 门禁挡着 —— 一旦某账号 Cascade 目录记为已同步,connect 同步
对它永久不可达,它自己的 per-key 资格压根没被查过。

"只覆盖部分路径"第五次,形态是新的。**修完一个 latch 后问:到达这个 latch 的路径上
还有几个 latch?**

### 4.4 未提交的修复会被突变循环的 git checkout 吃掉

本轮发生**两次**:我在 mutation loop 里用 `git checkout -- <file>` 还原突变,
把同一文件里**尚未提交的真修复**一起还原了,然后下一个突变测的是"修复缺失"而不是
"突变生效",读数完全是假的。

**纪律:先提交修复,再跑突变验证。** 或者用 `git stash` 之外的还原方式。

### 4.5 元守卫按逃逸点枚举,不按 flow

ACP vision 重路由不是 `selectBackend` 的 flow,是 `devin_connect` 逃进
`special_agent`,按 flow 枚举的守卫看不见它。`drought-gate-reachability` 因此枚举
**块内门禁之上的每个 `return`** 并要求每个登记豁免理由,且带"守卫的守卫"(枚举
结果为 0 即失败)—— 一个不再匹配任何真实 `return` 的枚举会永远通过。
