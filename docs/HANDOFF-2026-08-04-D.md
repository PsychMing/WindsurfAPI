## 5. 本轮最该记住的

台账第十二轮有完整版。两条会直接害到下一个人的:

### 5.1 "更正"比新增声明更危险

我判定台账第十一轮那句"已加测试钉住"是假的,写成一条更正落进台账,还在 commit message 里
说这是"注释声称有覆盖而实际零断言"的又一次。

**那条更正是错的。守卫一直在** —— `strict-usage-total.test.js`,源码扫描形态,它的失败消息
里甚至预先写好了"哪天流式路径真的记账了就删掉这条"。

怎么错的:grep 提到 `recordAccountSpend` 的测试文件(它命中了),再对命中文件 grep
`stream|cascade`(它又命中了),然后**看着命中行判断那是 usage 算术测试,没打开读**。两次
grep 都指向了正确的文件,我在最后一步用眼扫过去就下了结论。**是全量门禁抓到的,而且是在
修复已经提交之后。**

为什么这类错误特别贵:新增声明会被下一轮审;而"我核过了,上一轮那句是假的"会让下一个人
**停止怀疑**这个位置。

**动作**:要断言"这个面没有守卫",除了 grep 行为关键字,还要 grep**被守对象的名字**在
`test/` 下的全部命中并**逐个打开读**。命中少的时候成本是几十秒。另:源码扫描形态的守卫在
按行为搜索时是隐形的。

### 5.2 一条 SURVIVED 先问"这段代码今天会被执行吗"

本轮两条 SURVIVED,处置**相反**:

- FREE_REACHABLE 兜底 → **压根不执行**,是我自己上一个 commit 写的死代码 → 删
- `known()` existence 项 → 会执行,但没有输入能让它说话 → 记 `expectCaught: false` + 钉前提
