## 1. 接手第一步

```bash
cd /Users/dwgx/Documents/Project/WindsurfAPI
git status --short                             # 期望:干净
git rev-parse master origin/master             # 期望:相同
git describe --tags master                     # 期望:v3.9.19-N-g…(带后缀是正常的,见下)
npm run test:release                           # 期望:3462 / 0(265 个文件)
for s in test/mutations/*.json; do npm run mutate -- "$s"; done   # 期望:六个全绿
```

**不要用 `git describe --exact-match`。** tag 之后一旦落了文档 commit,它就 `fatal`,而那是
正常状态。带 `-N-g…` 后缀说明 master 领先 tag N 个 commit;只要那 N 个不含行为变更,不需要发版。

### 三条会立刻绊住你的操作纪律

1. **突变循环启动后就不要碰仓库。** 它每一步都在 `写入 → 跑测试 → git checkout HEAD -- 还原`,
   期间任何别的编辑都会被 guard 6 判脏并中止整轮。要并行干活就去 worktree。
2. **commit 前先切分支。** `.githooks/pre-commit` 拒绝在 master 上 commit,而它拒绝时你那次
   `git add` 已经做了 —— 工作树仍是脏的,紧接着跑突变会被 guard 1 再拒一次,看起来像两个
   毫不相干的失败。
3. **别跑 `test/_research/responses-cache-hit-seq.test.js`。** 它 2 条失败(**在 v3.9.18 之前
   就红**),而且**会写自己的 fixture** —— 误跑一次工作树就脏。`run-test-shard.mjs` 只取
   `test/*.test.js` 顶层,所以 `_research/` 从来不在门禁口径内,这两条不是回归。

## 4. 最该记住的几条

台账第十三轮有完整版。这里只留判别动作。

### 4.1 钳住取值范围不等于钳住语义

v3.9.18 给 digest 上限加了 `Math.min(x, 32000)`。对 `1e9` 有效,对 `0.5` **完全失效** ——
`Math.min` 忠实地保留了 0.5,而语义反转发生在下游:消费者是 `slice(-n)`,而 `slice(-0.5)`
=== `slice(0)` === 整个字符串。实测 `MAX_CHARS=0.5` 送出全部 50000 字符,**正是那道钳要挡的
后果**。v3.9.19 加 `Math.floor` 补上。

**这道钳失败不是因为它写错了,而是因为它对的。**

**动作**:给数值旋钮加钳之后,接着问"这个数最终被谁消费,那个消费者对非整数、对 0、对边界值
的行为是什么"。

### 4.2 文档里写行号 = 写一个会被下一次编辑推走的引用

同一个会话里踩两次:

- 台账导航写"实测:第 1150 行",**在写下的瞬间就是错的** —— 我量的是编辑前的文件,而把它推到
  1154 的正是同一个 commit 的那处编辑。
- 交接 §6.6 写 `rescueThinkingOnly` 在 119/228/334/559,一天后实际是 119/234/340/565 ——
  我加 `Math.floor` 的注释把它们推下去了。

**动作**:要么别写行号,要么在**最终状态**上重测。稳定的指路方式是 `Ctrl-F` 一个字符串。

### 4.3 突变 anchor 按整行匹配,所以任何包裹式改写都会打断它

一天被打断三次:#241 合并往判据里插 `hasTools`(两条)、我自己的 `Math.floor` 包住表达式
(一条)。第三次发生在我把前两条写进台账**之后**。

**动作**:anchor 锚**表达式**,不锚整行(去掉行首缩进与 `if (`)。表达式比整行耐改写。
例外是那种 replacement 要删掉条件本身的突变,它必须锚含 `if (` 的整行。
改完 `src/` 一定跑一遍完整突变循环 —— **测试套件不跑 spec,门禁全绿看不见 anchor 失配。**

### 4.4 "共 N 处"里的 N 也是需要测量的数字

交接与 merge message 都写了"三处重新 spread(3295/**3437**/3454)",实际**四处**(漏了 3229),
而 3437 这行不存在(是 3435)。结论没错(3229 同样保留 `.tools`),枚举错了。`grep -c` 一次
就能避免。

### 4.5 一个碰巧正确的未测量数字,比一个错的更难发现

交接曾写"六个 spec 共 60 条:56 CAUGHT + 4 漏网",而其中一个 spec 的 baseline 已过期、
guard 2 在第一条突变之前就中止它 —— 那 60 条里最多跑了 49。修完重跑,分布**恰好就是 56 + 4**。

**数字是对的,它作为"我跑过"的证据是假的。** 而它旁边的数字全都真实,所以它借到了那些数字的
可信度;接手的人按清单跑出红,第一反应是怀疑自己的环境。

**动作**:每个数字要能回答"这一次是谁跑出来的"。**存量数字不能当基数** —— 我曾把 baseline
从"记录里的 71"加"新增的 3"算成 74,真值 79。要一个计数就去测它。

### 4.6 说"这个 PR/这轮引入了 X"之前,先看邻居有没有同一个 X

我一度把"空串静默关掉 digest"记成 #241 的缺陷,驱动核实后不是:`Number('') === 0` 是那个文件
里**四个旋钮共有的既存约定**。处置因此完全相反 —— 不是改代码,而是改那句说谎的注释。按"PR
缺陷"处理会去动既存部署的行为,为一个不存在的缺陷。

反方向同样成立:**新增旋钮时去读邻居的伤口。** #241 真正的缺陷是新旋钮缺上限,而同一个函数
里的同类旋钮早就因为同一个洞加过钳,教训就写在它的注释里。**新代码不会自动继承邻居学到的。**

### 4.7 一个只有一个可达取值的旋钮,比没有旋钮更糟

`rescueThinkingOnly` 在 #241 之后成了死配置(默认 `true`、两个调用点都传字面 `true`、无任何
测试传 `false`)。已删(`866da63`,未发版 —— 零行为变更)。

它读起来像一个变化点,评审者必须为它推理;而任何冲着它去的突变守卫,守的是到不了线上的代码
—— 正是 v3.9.13 那条 medium 缺陷的形状。

**动作**:加一个 opt-out 参数时,同时写一条传 `false` 的测试。**那条测试才是让它成为旋钮而
不是装饰的东西。** 没有它,下一轮就该把这个参数删掉。

## 5. fan-out 复核这套流程本身的两条

v3.9.19 那轮用了 15 个 lens + 每条发现一个独立对抗验证器(81 条候选 → 40 条唯一 →
**35 CONFIRMED / 5 REFUTED**)。两条关于流程的:

- **一次 40 个验证器并发会被网关限流。** `pipeline()` 是全部并发:前 16 个返回、17–39 全部
  stall 且每个重试 6 次都 stall。改成 4 个一批顺序跑,58 条全部返回。台账第五轮记过"单个
  agent 跑太久会丢全部结果",**扇出太宽是同一条的另一个形态**。
- **验证器必须有 `UNVERIFIED` 第三态。** 第一版脚本把"没返回"和"没问题"混进同一个
  `filter(Boolean)` —— 那正是 `confirmed: 0` 被当成"通过"的形状。而 synthesizer 最后也
  stall 了,裁决却都在 `journal.jsonl` 里:**agent 挂了不等于结果没了,先去 journal 捞。**

**5 条 REFUTED 也是产出**:验证器用 `merge-base --is-ancestor` 证明一条不在审查范围内、拿
邻居惯例反驳两条"broken ref"、还有一条指出报告者只读了 native 那一支而漏了第二个无门的发射点
——**并在反驳过程中发现了另一条未记录的缺陷**。

发版"的判据、notes 的体例)。

**判别动作**:一份"怎么做 X"的文档,要**照着做一遍**才算读过。逐句读它会显得合理 ——

## 9. 出口 parity 复核(2026-08-06 第二轮)

这一轮问的是"**同一条不变式在四条出口协议上是否都成立**" —— 挑这个面是因为它是本仓库
复发最多的形状(记过 6 次),而台账的方法论笔记说得很直接:被审过的地方是硬的
(鉴权 30+ 次、协议层 fuzz 190+ 次,零缺陷),**没审过的地方才有货**。

四条出口:`chat.js`(OpenAI)· `messages.js`(Anthropic)· `responses.js` · `gemini.js`。

### 9.1 查出一条真缺陷:Gemini 静默丢掉全部工具参数

`gemini.js` 文件头第 9 行自己写着 "Mirrors src/handlers/messages.js"。而 messages.js 的
**B4** 修复没镜像过来:两处 `catch {}` 把无法解析的 `arguments` 塌成 `{}`。同一份上游
payload 实测:

```
Anthropic 出口   input = {"__raw_arguments":"{\"file_path\": \"/etc/passwd\", …"}  + log.warn
Gemini   出口   args  = {}                                                        零日志
```

已修(`aeb18dd`):抽 `parseToolArgs()`,非流式与 `flushToolCalls()` 两个站点都调它,
原串放在 `__raw_arguments`(与 Anthropic 同键名)。**这是第七次。**

**判别动作**:一个文件声称"mirrors X",就把 X 里带编号的修复逐条对过去。这条声明本身
是最好的检查清单,而它在这里躺了一个月没人当清单用。

### 9.2 一条既有测试把缺陷钉成了期望行为

`test/gemini.test.js` 有 `it('survives malformed tool-call argument JSON (args -> {})')`,
断言 `deepEqual(args, {})`。它**真正测的是"不抛异常"**,但把空对象写进期望之后,数据丢失
在后来每个读者眼里都像是刻意设计 —— 我改完代码正是它先红的。

**判别动作**:写"survives / 不崩"这类测试时,断言要**只钉不崩那一条**。把当前的返回值
顺手写进 `deepEqual`,等于把当时的缺陷升级成契约。测试名里带括号解释返回值(`(args -> {})`)
是这个毛病的显式征兆。

### 9.3 `gemini.js` 此前零突变 spec —— 这就是它没被发现的原因

71 条测试从未被突变验证过。新增 `test/mutations/gemini-egress-parity.json`(7 条,全 CAUGHT)。
仓库突变总数 **67 → 74**,声明漏网 **4 → 4**(新 spec 零漏网)。

**两条关于突变本身的**:

1. **第一次跑出一条漏网,是我的突变锚错了,不是守卫有洞。** 我锚在 `error()` 的早退卫兵
   (`if (this.finished) return`)上,而真正的 latch 是它末尾的 `this.finished = true` ——
   改卫兵不改 latch,`finish()` 照样早退,**这条突变压根没注入它声称的缺陷**。理由已写进
   spec 的 `name` 字段,免得下一轮有人把锚改回去。
2. **我把"日志行被删"记成声明漏网,理由是"断言日志输出需要 harness" —— 不成立。**
   `test/retry-rescue-budget-split.test.js:198` 从第十一轮起就在替换 `log.warn` 收集输出。
   **这和 PR #242 那条 settle-flush survivor 是同一个毛病:"工具还没建"而工具就在隔壁文件里。**
   已补两条断言(含一条负对照:合法 payload 零日志,否则断言在"无条件记日志"的版本上也绿)。

### 9.4 查证但**未修**的三条(留着理由,别当遗漏重新捡起来)

- **`mapFinishReason` 的 `|| 'STOP'` 兜底对 `finish_reason:'error'` 会翻成正常结束** ——
  正是 special-agent.js 的 "H2" 注释要防的后果。但**不可达**:那条路径先发 error 帧,
  `error()` 会 latch `finished`,finish chunk 在翻译前就被丢掉。按 §4.7,给到不了的分支加
  映射等于加一个评审者必须为之推理的假变化点,所以改成把**让它无害的前提**写进注释 + 用
  测试钉住。我一度加了 `error: 'OTHER'` 又撤掉。
  *判别动作*:确认一条缺陷"可达"要走完整条链,不能只驱动出口函数 —— 我第一次的探针直接
  调 `openAIToGemini`,而生产上那个值到不了它。

### 9.6 发版失败了一次,而失败的是我这一轮加的守卫

   **当时那个 tag** 的记录 —— 那句话**写下时为真**,在一份只追加的历史记录里,过期的旧声明
   正是它该有的样子。

   毛病在一天内的第四次,而这次是守卫自己在两分钟内拦下的,不是我读出来的。**这就是把纪律
   换成机制的全部意义。**
